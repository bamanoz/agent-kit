## Контекст

Работа выполняется агентами в нескольких сессиях, а крупные решения могут
меняться, включая состав и границы компонентов. Одного семантического
хранилища недостаточно для точных контрактов, review и связи поведения с
версией кода.

## Решение

Git является источником истины по baseline, архитектурным ревизиям, ADR,
формальным контрактам, коду и тестам. Mempalace (крыло `{{WING}}`)
используется для оперативного контекста, причин решений, истории, блокеров и
ссылок на Git-артефакты.

Порядок источников:

1. Код, тесты и машинные контракты определяют фактически реализованное
   поведение.
2. `project-memory/` определяет baseline, архитектурную ревизию, принятые
   решения, контракты и открытые вопросы.
3. Согласованные требования проекта определяют целевое внешнее поведение.
4. Mempalace хранит причины решений и историю.

Внешние источники не переопределяют активный baseline: обнаруженное
расхождение сначала оформляется как `OQ-*` или `CHG-*`.

## Альтернативы

- Только Mempalace: отклонено из-за отсутствия надежного versioning, diff и
  машинной проверки контрактов.
- Только Git: отклонено, поскольку агентам нужен семантический поиск по
  причинам решений, истории и результатам прошлых сессий.

## Последствия

- Каждое существенное решение получает Git-артефакт.
- Mempalace checkpoint обязан ссылаться на соответствующие файлы.
- При расхождении точных сведений приоритет у Git и фактических тестов.
- Архитектурные развороты оформляются новой ревизией без удаления истории.

## Проверка

- Наличие `project-memory/baseline.yaml` и реестров.
- Наличие комнат реализации в Mempalace.
- Выполнение `project-memory/session-protocol.md` в последующих сессиях.
